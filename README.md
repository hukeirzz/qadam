# Qadam

**Qadam** («шаг» по-кыргызски) — веб-платформа, с помощью которой учителя готовят учеников к **ОРТ** (общереспубликанскому тестированию, вступительному экзамену в вузы Кыргызстана).

Раньше Qadam был мобильным приложением с играми и рангами. С 30 октября 2026 года мобильного приложения нет: остался **один сайт** с двумя кабинетами — для учителя и для ученика. Этот документ описывает, как всё устроено после первого этапа: продукт, код, база данных.

> Этап 1 (готов): учительская платформа, кабинет ученика, тесты с чертежами и фото.
> Этап 2 (дальше): генерация вопросов и чертежей ИИ, свой домен.

## 1. Что умеет Qadam

### Две роли

| Роль | Откуда берётся аккаунт | Что видит |
|---|---|---|
| **Учитель** (в БД — `staff`, роли `director`/`coordinator`) | Создаёт владелец платформы вручную в Supabase | Весь кабинет учителя: `/`, `/analytics`, `/results`, `/students`, `/tests` |
| **Ученик** (в БД — `students`) | Регистрируется сам на `/register`: gmail + пароль + имя + **код класса** | Только кабинет ученика: `/student/...` |

Вход для обоих один: `/login`. После входа сайт сам определяет роль и ведёт в нужный кабинет. Учитель не может открыть кабинет ученика и наоборот (проверка стоит в `layout.tsx` каждой группы страниц), а данные дополнительно защищены на уровне БД (см. раздел 5).

### Жизненный цикл ученика и теста

1. **Класс.** Учитель создаёт класс («11А»), БД сама генерирует **код класса** из 6 символов (`classes.promo_code`). Код можно перегенерировать, если он утёк.
2. **Регистрация ученика.** Ученик вводит имя, gmail, пароль и код класса. Триггер БД `handle_new_user` находит класс по коду и сразу записывает ученика в этот класс и в школу класса.
3. **Смена класса.** Ученик может поменять класс только введя код нового класса (функция `change_class_by_code`). Напрямую поменять `class_id` нельзя — этому мешает триггер `students_lock_class`. Учитель может перенести ученика между классами своей школы сам («⋯» → «Перенести в другой класс»).
4. **Создание теста.** Учитель в конструкторе («Тесты школы» → «Создать тест») выбирает уровень сложности (I/II/III), раздел (математика/геометрия), тему, количество вопросов, потом редактирует вопросы (текст, 4 варианта, верный ответ, фото или чертёж), потом выбирает учеников. Платформа подсказывает «рекомендованных» — тех, у кого по теме точность ниже 65%.
5. **Назначение.** Тест видят **только назначенные ученики** (таблица `school_test_students`). Назначения «на весь класс» как отдельной сущности нет — это просто назначение каждому ученику класса.
6. **Решение.** Ученик на главной видит «Актуальные задания», жмёт «Начать», отвечает на вопросы по одному (сразу видит, верно или нет, и пояснение), в конце получает результат.
7. **Первая попытка — главная.** Результат первой попытки сохраняется в `school_test_results` (одна строка на пару «тест + ученик»). **Только он идёт в аналитику.**
8. **Пересдача.** Решённый тест можно пересдать сколько угодно раз. Пересдачи лежат отдельно (`school_test_retakes`), ученик их видит, но **в аналитику они не попадают** — иначе можно было бы «накрутить» успеваемость.
9. **Статус задания у ученика.** Зелёный «Без ошибок» (лучшая попытка 100%) или оранжевый «Есть ошибки». Состояния «в процессе» в БД нет: тест либо не решён, либо решён.

### Что видит учитель

- **Главная** (`/`) — сводные плитки (учеников, средний балл ОРТ, пробные, слабые темы), динамика пробных экзаменов, ученики, которым нужна помощь.
- **Аналитика** (`/analytics`) — те же плитки, динамика пробных, распределение баллов, **тепловые карты по темам для каждого уровня** (точность по первым попыткам школьных тестов).
- **Добавить результаты** (`/results`) — ручной ввод результатов **пробного ОРТ** (по разделам: математика, геометрия, грамматика, аналогии, чтение и сумма; максимум 245, проходной 110).
- **Ученики** (`/students`) — список с поиском и фильтром по классу, управление классами и кодами, меню «⋯»: «Перенести в другой класс», «Удалить ученика» (удаляет аккаунт и все его данные безвозвратно). Клик по имени — профиль ученика (`/students/[id]`).
- **Тесты школы** (`/tests`) — список тестов, конструктор, у каждого теста страница с результатами, списком «не проходили» и всеми вопросами с чертежами и верными ответами (`/tests/[id]`).

### Что видит ученик

- **Главная** (`/student`) — приветствие, сводка «Назначено / Решено», полоса «Выполнено», «Актуальные задания», «История тестов» (с пересдачей).
- **Успеваемость** (`/student/progress`) — динамика пробных и тепловые карты по уровням.
- **Профиль** (`/student/profile`) — имя, класс; имя и класс (по коду) можно менять на месте.
- **Прохождение теста** (`/student/tests/[id]`, пересдача — `?retake=1`).

### Вопросы с чертежами и фото

У вопроса может быть:
- **Фото** (`image_url`): учитель загружает снимок (чертёж из учебника). Перед отправкой фото сжимается до 1280 px.
- **Чертёж** (`figure`, JSON): **не картинка**, а короткое описание фигуры (точки, отрезки, окружности, углы, оси координат). Рисует его компонент `figure.tsx`: подписи и числа всегда совпадают с условием. Умеет плоскость и стереометрию (куб, пирамида, цилиндр, конус, оси, сечения, невидимые рёбра пунктиром). Именно этот формат на этапе 2 будет выдавать ИИ — это дёшево (сотни токенов на чертёж) и надёжно.

## 2. Технологии

- **Сайт:** Next.js 16 (App Router, Turbopack), React 19, Tailwind CSS 4, TypeScript.
- **БД и вход:** Supabase (Postgres + Auth + Storage), проект Qadam, регион Франкфурт.
- **Хостинг:** Vercel (регион `fra1`, чтобы сайт был рядом с БД).
- **Монорепозиторий:** npm workspaces + Turborepo.

Правило архитектуры: **страницы никогда не импортируют `@supabase/supabase-js` напрямую** — всё общение с БД идёт через пакет `packages/api-client`. Права доступа решает не код сайта, а **RLS** (политики безопасности строк) в самой БД.

## 4. База данных (Supabase, проект Qadam)

Схема собирается миграциями из `supabase/migrations/` (по порядку имён). Первые миграции — история времён мобильного приложения, последние (`…0731…`) — текущая платформа; `20260731000008_cleanup_legacy.sql` удалил всё, что осталось от игр и рангов. Историю не переписываем: любая новая правка — новая миграция.

### Таблицы

**Школа и люди**

| Таблица | Что хранит |
|---|---|
| `schools` | Школы (сейчас одна — «Международная школа Билимкана»). Название и служебный код школы. |
| `classes` | Классы школы: название («11А») и **код класса** `promo_code` (6 символов), по которому регистрируются ученики. |
| `staff` | Учителя: имя, роль (`director`/`coordinator`) и школа. Строка создаётся триггером при создании аккаунта учителя. |
| `students` | Ученики: имя, школа, класс (`class_id`) и подпись класса (`class_label`). Строка создаётся триггером при регистрации. Одна запись = один аккаунт `auth.users`. |

**Справочники**

| Таблица | Что хранит |
|---|---|
| `subjects` | Пять разделов ОРТ: `math`, `geometry`, `analogies`, `reading`, `grammar`. На них ссылаются темы и тесты. |
| `topics` | Темы (15 штук): раздел, название, порядок. |
| `topic_levels` | На каких уровнях сложности (basic/medium/high) преподаётся тема — 45 строк. Тема + уровень = то, что ученик видит как «Тема II». |

**Школьные тесты**

| Таблица | Что хранит |
|---|---|
| `school_tests` | Тест: школа, название, раздел, тема, **уровень**, опубликован ли, кто создал. Пока `published = false`, тест не виден ученикам (так создание не оставляет «полуготовых» тестов). |
| `school_test_questions` | Вопросы теста: порядок, текст, пояснение, **`image_url`** (фото) и **`figure`** (JSON-чертёж). |
| `school_test_options` | Варианты ответа вопроса: текст и флаг `is_correct`. |
| `school_test_students` | **Кому назначен тест.** Только эти ученики видят тест. |
| `school_test_results` | **Первая попытка** ученика: балл, всего вопросов, время. Уникально по паре «тест + ученик». Единственный источник аналитики. |
| `school_test_retakes` | Пересдачи (вторая и далее попытки). В аналитику не попадают. |

**Пробные экзамены ОРТ**

| Таблица | Что хранит |
|---|---|
| `mock_exams` | Пробный экзамен школы: название и дата. |
| `mock_results` | Баллы ученика на пробном по разделам (`math`, `geometry`, `grammar`, `analogies`, `reading`) и сумма `total` (максимум 245). Вводит учитель на странице «Добавить результаты». |

**Хранилище файлов (Storage)**

| Бакет | Что хранит |
|---|---|
| `question-images` | Фото к вопросам. Читать может кто угодно по ссылке (имена — случайные), загружать и удалять — только учитель в папку своей школы (`{school_id}/…`). Лимит 5 МБ, форматы jpeg/png/webp. |

### Функции и триггеры

| Имя | Что делает |
|---|---|
| `handle_new_user` (триггер на `auth.users`) | При создании аккаунта: учитель (`account_type = staff`) → строка в `staff`; иначе ученик → строка в `students` с классом по коду из регистрации |
| `check_class_code(code)` | Проверка кода класса на странице регистрации (доступна без входа) |
| `change_class_by_code(code)` | Ученик меняет класс по коду |
| `students_lock_class` (триггер) | Запрещает ученику менять класс/школу напрямую — только через функцию выше |
| `staff_move_student(ученик, класс)` | Учитель переносит ученика в другой класс своей школы |
| `staff_delete_student(ученик)` | Учитель удаляет ученика своей школы: удаляется аккаунт и каскадом всё остальное |
| `regenerate_class_code(класс)` | Новый код класса; `gen_promo_code()` придумывает неповторяющийся код |
| `is_staff()`, `current_school_id()` | Помощники для политик: «текущий пользователь — учитель» и «его школа» |
| `staff_owns_school_test(тест)` | Тест принадлежит школе вошедшего учителя |
| `can_student_see_school_test(тест)` | Тест опубликован и назначен этому ученику |
| `school_test_result_normalize` (триггеры на `school_test_results` и `school_test_retakes`) | Сам проставляет `total` по числу вопросов и ограничивает `score`, чтобы нельзя было записать, например, 100 из 5 |

### Безопасность (RLS)

На всех таблицах включена защита строк. Главные правила:
- Учитель видит и меняет данные **только своей школы**.
- Ученик видит **только свои** результаты и **только назначенные ему** тесты.
- Ученик не может записать пересдачу, пока не сделал первую попытку, и не может менять результат первой.
- Класс ученик меняет только по коду, учитель переносит любого ученика своей школы.
- Удаление аккаунта идёт через функцию с проверкой школы; клиенту прямой доступ к `auth.users` закрыт.
